## Key files explained

### `ios/Podfile`
Cocoapods spec. Pulls the Expo + React Native autolinked pods. Run `pod install` (or `npx pod-install`) from `ios/` after copying the project to a Mac.

### `ios/prote.xcodeproj/`
Xcode project metadata — open `ios/prote.xcworkspace` (created after `pod install`) in Xcode, not the `.xcodeproj` directly.

### `ios/prote/AppDelegate.swift`
Swift-based App Delegate that boots Expo's React Native host. No manual edits required; it autolinks all Expo modules including:
- `expo-image-picker` (camera & photo library)
- `expo-store-review` (App Store rating prompt)
- `expo-router` (file-based navigation)
- `expo-font` (Cormorant Garamond + Jost loaders)
- `react-native-svg` (progress ring + bar charts)
- `@react-native-async-storage/async-storage` (profile + meals cache)

### `ios/prote/Info.plist`
- `CFBundleDisplayName`: `proteā`
- `CFBundleIdentifier`: `$(PRODUCT_BUNDLE_IDENTIFIER)` → `com.anonymous.frontend`
- `NSCameraUsageDescription`: **"Snap meal photos to log protein"**
- `NSPhotoLibraryUsageDescription`: **"Pick meal photos to log protein"**
- App Transport Security: HTTPS-only (default)
- `UISupportedInterfaceOrientations`: portrait only
- `UIRequiredDeviceCapabilities`: `arm64`

### `ios/prote/prote.entitlements`
Minimal entitlements file. Add `aps-environment` and `associated-domains` here when you wire up push notifications or universal links later.

### `ios/prote/SplashScreen.storyboard` + `Images.xcassets/SplashScreenLogo.imageset/`

### `ios/.xcode.env`
Tells Xcode where to find `node` during build (set by `xcode-build-scripts`). Do not commit local overrides; use `.xcode.env.local`.

## How to build locally on a Mac

```bash
# 1. Copy /app/frontend/ to your Mac, OR clone the repo there.
cd frontend
npm install         # or yarn
cd ios
pod install         # installs Cocoapods deps
cd ..
npx expo run:ios    # builds + opens the simulator
```

If Xcode complains about signing, open `ios/prote.xcworkspace`, select the `prote` target → Signing & Capabilities → tick "Automatically manage signing" and pick your Team.

### Known Xcode 16 / Xcode 26 build error — already fixed in this project

**Symptom**: Build fails on the EXConstants (or another Expo pod) target with
`Command PhaseScriptExecution failed with a nonzero exit code`.

**Cause**: Xcode 16 introduced `ENABLE_USER_SCRIPT_SANDBOXING = YES` as the
default. Several Expo pod build scripts write files outside the sandbox
during build, so every PhaseScriptExecution returns non-zero. Xcode 26
inherits this default.

**Fix shipped in this project**: the `Podfile` `post_install` hook now sets
`ENABLE_USER_SCRIPT_SANDBOXING = NO` on every pod target AND every native
target in the user project. If you regenerate the ios folder via
`expo prebuild --clean`, the patched Podfile is preserved.

**If you still see the error after pulling fresh code**:
```bash
cd ios
rm -rf Pods Podfile.lock build
pod install
cd ..
# Then Xcode: Product → Clean Build Folder (⇧⌘K) → Run
```

## How to ship to TestFlight / App Store via Emergent

The simplest path is the green **Publish** button in the Emergent toolbar — it uses EAS Build under the hood and produces a signed `.ipa`. No local Mac required.

```
Emergent → top-right → Publish → iOS → choose "TestFlight" or "App Store"
```

EAS will use the generated `ios/` folder as the source of truth, so any changes you make in Xcode (icons, capabilities, signing) should be committed before publishing.
